Implementó:

    `GeneradorReportePdfTest`.

**Decisiones autónomas relevantes:**
1. **`programa` y `periodo` ambos requeridos para calcular la sección (no
   solo `programa`):** sin `periodo` no hay con qué invocar
   `CalcularResultadoAutoevaluacionUseCase.ejecutar(programa, periodo)` de
   forma significativa; se trató como un prerrequisito de datos, igual que
   la cohorte para la tasa de deserción.
2. **"Omitida si no hay datos suficientes" se interpretó en dos niveles:**
   (a) periodo mal formado → `FormatoPeriodoInvalidoException` capturada y
   tratada como ausencia de datos (el reporte no debe fallar completo por un
   parámetro de filtro inválido, mismo principio que `sinDatosInsuficientes`
   para las demás secciones); (b) resultado calculado pero totalmente vacío
   (sin ningún promedio presente) → se omite igual, porque no hay nada que
   mostrar. Un resultado con *algún* dato presente (aunque sea parcial) sí
   se incluye completo, con "Sin datos" en las ausencias puntuales — igual
   que el dominio ya representa ausencias como `null`, nunca como `0`.
3. **La sección se omite por completo (sin encabezado) cuando no hay datos,
   a diferencia de "Indicadores de Calidad" y "Respuestas de Encuesta", que
   siempre muestran su encabezado con un mensaje de reemplazo:** esas dos
   secciones agregan datos de todo el sistema (pueden estar vacías pero
   siguen siendo relevantes como secciones del reporte); el resultado de
   autoevaluación es específico de un programa que ni siquiera se pidió
   calcular si no se indicó `programa` — no tiene sentido imprimir un
   encabezado para un cálculo que no se solicitó.
4. **Tabla única con tres niveles ("Global"/"Factor"/"Característica") en
   vez de tres tablas separadas:** reutiliza el mismo helper `tabla(...)` ya
   usado por las otras secciones sin necesidad de un nuevo tipo de layout, y
   mantiene la sección en un tamaño razonable para catálogos grandes (12
   factores, 48 características en el modelo real).
5. **Catálogo de ponderaciones de prueba de `GenerarReporteEjecutivoUseCaseTest`
   definido localmente (un factor, dos características) en vez de
   reutilizar el de `ConfiguracionCasosDeUsoDePrueba`:** ese test vive en el
   paquete `application`, no en `infrastructure.web`; mantener su propio
   catálogo mínimo evita una dependencia cruzada entre paquetes de prueba
   solo para una constante de datos.
